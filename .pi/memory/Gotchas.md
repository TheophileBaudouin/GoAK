- **2026-08-07** — User request asked to add an "exception" to a supposed kit rule avoiding CGO/Objective-C/native bindings — no such general rule exists in the kit. Zero-CGO is only a library-selection preference in catalog fiches plus factual cross-compilation guidance; rules/core/philosophy even says "Prefer the standard library or platform capability". Applying the request literally would have created an exception to a non-existent rule and touched existing artifacts needlessly. → **Before implementing any request framed as "exception to a rule", "override the rule", or "this conflicts with the kit policy": verify the supposed rule actually exists in the current tree (grep rules/, knowledge/, recipes/) AND in committed decisions (git log / Decisions.md). If the premise is false, tell the user and serve the underlying intent with positive guidance in the new artifact instead of modifying existing ones.**

- **2026-08-06** — The kit's Python validators import PyYAML but nothing declared the dependency — the local gate only passed because PyYAML happened to be installed ad-hoc; the CI comment even claimed "Python (stdlib only)". Fresh machines could not run validate-cognitive.py / validate-kitv2.py / build_index.py. Also, `go test -coverprofile ./...` counts the 15 probe main.go files at 0% (they have no unit tests — they are executable scenarios), keeping the CI coverage floor permanently red at ~60%. → **Before claiming a gate is reproducible: declare every non-stdlib dependency (pin PyYAML in .agent/validators/requirements.txt and pip-install it in CI). When a coverage floor is measured, define the measured surface explicitly: exclude executable scenario mains (probes/) from the aggregate — they are verified by probes/run.sh in the same CI run, not by unit-test coverage (D-2026-08-06-13). Re-run the CI-equivalent coverage command exactly before a release.**

- **2026-08-06** — The Pi extension loader (jiti) resolves TS-style `.js` import specifiers to `.ts` files, and Node ≥ 23.6 imports `.ts` natively (type stripping). If the shared scoring module had been imported with an explicit `.ts` extension in the extension, the ESLint import rule would reject it; if the gate runner had re-implemented the scoring in Python, it would have drifted from the runtime. → **For runtime+test-shared TypeScript: keep the pure logic in a dependency-free module under .pi/extensions/; the extension imports it with the TS-convention `.js` specifier (jiti maps to .ts, verified experimentally), and the metaproject gate imports the same .ts directly with node ≥ 23.6. Never re-implement scoring in the test language — shared module is the only way to guarantee zero divergence.**

- **2026-08-06** — Adding id cross-references to knowledge/stdlib/*.yaml relationships failed validate-cognitive.py while validate-kitv2.py passed: the cognitive validator resolves stdlib relationship targets against the OFFLINE CATALOG known-ids set (graph_objects of the bundle catalog), not the full knowledge graph — so source:go:sync or any pattern/anti-pattern id in a stdlib pointer's relationships is "unresolved" even though the file exists in the tree. → **stdlib pointers are pointer-only by contract (Z2 §2): their relationships.references must contain URLs only (like the existing 24 pointers). Keep pattern/anti-pattern cross-links as free text in selection/limits, never as relationship targets; the two validators resolve ids against different known-id sets (kitv2 = full graph, cognitive = offline catalog).**
