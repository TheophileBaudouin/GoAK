# Plan — structure.md contract + governance hardening (metaproject)

## Goal

Implement decision RDN-003 at the metaproject level: every project generated by
the kit embeds a `structure.md` — a **reading map for a non-developer**, not a
file inventory. This session produces the five mandated deliverables inside the
allowed scope (`KIT_CHARTER.md`, `.agent/**`, `.pi/memory/**`,
`.pi/prompts/kit-audit.md`, `docs/**`). The `KitV2` mechanism (generator, rule,
template integration) is **specified here, not implemented here**; the next
`kit-audit` pass detects and drives it once this contract is authoritative.

## Context

- **RDN-003 (ruled)**: no forced identical project structure across project
  types. Each generated project carries a `structure.md` reading map. This
  complements — does not replace — `KitV2/rules/core/philosophy/SKILL.md`
  (which already refuses a universal imposed layout, and whose boundary states
  "prescribes no universal project layout"). The philosophy rule is **not
  touched**.
- **Charter**: `KIT_CHARTER.md` §3 defines seven cognitive layers; Layer 5 is
  Templates ("Templates assemble complete projects"). §16 holds the ten
  immutable core principles. §8 covers deterministic generation; §13 covers
  relationships.
- **Contracts**: `.agent/kit-governance/` Z5 (templates, MIT policy),
  Z11 (router), C2 (validator gate), Z2 (knowledge), C9/E dimension of
  kit-audit (absolute instructions), `.agent/instructions.md` §Enforcement
  registry (D-2026-08-05-15).
- **Research (2026-08-06, fresh researcher subagent)**: brief saved at
  `docs/research/2026-08-06-structure-md-generation.md`. Findings: a
  deterministic Go generator is feasible (`go list ./...` + template); standard
  dir roles (cmd/, internal/, pkg/) are inferable; **custom dir roles and
  semantic reading paths require human annotation** — this is a solvable
  "generated skeleton + human semantic enrichment" hybrid, **not a blocking
  obstacle**; drift defense via CI `git diff --exit-code` is a proven pattern;
  Go's `// Code generated ... DO NOT EDIT` marker is the canonical no-edit
  convention. No genuine technical obstacle on the Pi/Go side → **no question
  to Theo required for the generation-vs-validation default**.
- **Existing absolute-instruction governance**: `.agent/instructions.md`
  already records process absolutes with mechanical-control status
  (D-2026-08-05-15); kit-audit C9 verifies it per run.

## Constraints

- **Forbidden this session**: any modification under `KitV2/`.
- Allowed scope only: `KIT_CHARTER.md`, `.agent/**`, `.pi/memory/**`,
  `.pi/prompts/kit-audit.md`, `docs/**`.
- Language: English mandatory (D-2026-08-05-21).
- One modification at a time — never two deliverables in the same edit pass.
- One fresh-context subagent per deliverable (mechanism:
  `.agent/cognitive/subagent-contracts.yaml` + `context-policy.yaml`), me as
  the single writer.
- Charter changes are structural: this task is the explicit owner directive
  authorizing them.
- Every new charter constraint must be verifiable (validator C2 or an explicit
  review control) — an unverifiable rule is a hypothesis.

## Decisions taken in this session (delegated, no owner question needed)

- **Placement (D1)**: `structure.md` is a *produced artifact of generated
  projects*, not a knowledge type → **subsection of Layer 5 — Templates**, not
  a new cognitive layer. Rationale: layers type *knowledge artifacts*; a new
  layer for one produced document would inflate the type system and break
  §4 single-source-of-truth.
- **Generation vs validation (D2)**: generation-first default
  (deterministic generator + drift gate), with documented objective exception
  conditions for validation-only acceptance of a hand-written file. No
  blocking technical obstacle found → default documented, no owner question.

## Steps

2. **D1 — charter §3 Layer 5**: add `structure.md` subsection — definition,
   mandatory minimal content (one-line role per top-level dir, typical reading

   (structure.md mechanism, relationship resolvability, router sole entry,
   category justification, absolute-instruction validator citation) + Phase E
   automation-gap rows.
6. **D5 — memory**: `.pi/memory/Decisions.md` (RDN-003 as ruled + structure.md
   method + placement + generation policy); `Gotchas.md` (technical limits
   from research).
7. **Fresh-context review** (read-only subagent) of the whole diff before
   declaring done.
8. **Final report**: decided / pending-for-owner / what the next `kit-audit`
   pass must fix in `KitV2`.
